①功能架构图

五大模块 + 全局机制。每个模块下列出原型中识别到的全部功能点；加粗为跨模块数据流枢纽。

P1 工作台（标书编辑主战场）
  • 项目上下文条：切换/编码/开标倒计时/招标人/详情入口
  • 文档预览：章节大纲滚动同步 / 文内搜索↑↓ / 字号 A± / 阅读进度
  • 废标检测：风险指数 0-100 / 三极分级 / 四型筛选 / 只看未处理 / 定位原文 / 修改建议+依据 / 标记已处理闭环 / 重新检测
  • 评分办法对照表（源自招标文件拆解）
  • 案例推荐：匹配度/时间排序 / 引用到本文档
  • 人员介绍：材料齐缺状态
  • 导出：Word / PDF / 检测报告（致命项拦截确认）
  • 缺件保护：无投标文件空态引导 / 无招标文件禁止检测
P2 项目库（投标台账）
  • 跟进中 / 已归档 双模式
  • 台账表格：项目/主陪/行业/开标时间/五阶段 stepper（落后提示）/客户含合作历史徽章/销售/平台
  • 搜索 + 主陪筛选 + 阶段筛选
  • 详情抽屉：信息 meta / 阶段推进与回退 / 招标资料 / 客户历史合作 / 跨页跳转（去检测/文档库/素材库）
  • 新建 / 编辑项目：表单校验 + 招标文件与公告上传
P3 文档库（拆解工作台）
  • 文档列表：招标/投标分类、绑定项目徽章、拆解状态
  • 拆解结构面板：招标抽 4 组（须知前附表/评标办法前附表/格式清单/章节目录）；投标抽 7 项（法代证明/授权委托/基本情况/财务/类似业绩/在履约/团队简历）
  • 拆解状态流转：未拆解 → 拆解中（进度） → 已拆解
  • 上传文档：类型选择 + 多文件 + 绑定三选（暂不/现有/新建并绑定）
  • 绑定 / 换绑 / 解绑
P4 素材库（编辑工作台）
  • 7 分类分组列表（资质/财务/业绩/人员/技术方案/商务模板/投标格式）
  • 素材四类型：表格（字段值行）/ 文本 / 图片 / 附件
  • 来源双轨：文档库拆解自动入库（去重）/ 手动上传新建
  • 编辑面板：改标题/分类/类型/标签/内容/换文件
  • 引用到项目（引用计数） / 删除（引用警告）
  • 搜索 + 分类筛选 + 来源统计
P5 系统设置
  • 通用：开机自启 / 数据目录 / 磁盘水位告警
  • AI 服务：GLM Key / 模型连接（原型弹窗已画）
  • 自动归档：扫描周期 / 收藏路径
  • 备份：每日 7 天滚动 / 手动还原
  • 规则设置：废标清单 / 抽取字段规则（编辑器二期）
全局机制（贯穿五页）
  • 单页五视图切换 + 面包屑；toast 轻提示；确认/拦截弹窗；详情抽屉
  • 项目上下文贯穿：切换项目带致命项确认；五页共用同一数据层
  • 跨页跳转：抽屉 → 工作台检测 / 文档库管理 / 素材库引用
  • 空态规范：未检测 / 无风险 / 无文档 / 无匹配
保护机制（红线）
  • 涉密零出域：默认涉密，非涉密才走 GLM，全调用审计
  • 缺件保护：无招标+投标文件禁止检测（弹窗引导上传）
  • 导出保护：存在致命项时导出前确认
  • 删除保护：素材删除提示引用次数、不可撤销警示

②技术架构图

单机 localhost · Windows 办公电脑 · CPU 串行纪律 · 数据不出本机。原型交互已验证 → 按此分层实现。

前端层
Vue 3 + Vite + TypeScript（单页应用，仅绑 127.0.0.1）
原型即规范：五视图路由 + 组件按 03-设计规范 v1.2 组件清单实现
views/ 工作台·项目库·文档库·素材库·设置components/ 风险卡·抽屉·弹窗×7·chips·steppertokens.css 方案CFeather 图标
API 层
FastAPI（uvicorn 单 worker，127.0.0.1:8000）
routers 与 PRD 功能点一一对应
/api/projects 台账+抽屉+阶段/api/documents 上传/列表/拆解/绑定/api/extract 拆解结构/api/materials 素材CRUD/引用/api/search 检索/api/checks 检测/api/rules 规则/api/paths 扫描/api/settings/api/export/api/audit
服务层
archive/ 扫描+watchdog 实时监听ingest/ 解析(OCR分流)+切片+索引extract/ 拆解抽取+素材harvest去重search/ FTS5 trigram+3gram兜底check/ 四态比对管线export/ openpyxl+Wordpreview/ 按页渲染llm/ GLM-4-Flash+涉密断言audit/ 审计workers/ 串行队列+定时扫描
拆解 = 解析(PaddleOCR 分流) → 结构化抽取(GLM 非涉密 / PP-Structure+正则 涉密) → 状态机 未拆解→拆解中→已拆解
数据层
SQLite（WAL）+ FTS5 trigram 虚拟表 + sqlite-vec 向量（[ai] 可选）
单文件库 data/db；原件 data/files；页图缓存 data/cache；备份 data/backup（7 天滚动）
AI 层
GLM-4-Flash 文本结构化/打标（非涉密）GLM-4V-Flash 图片理解（M3）PaddleOCR mobile 扫描件PP-Structure 表格+涉密兜底bge-small-zh 语义向量
涉密闸门：is_secret=1 一律本地管线，云调用入口断言 + 审计
交付形态
内嵌 Python 免安装 + 启动器（双击起服务+开浏览器）+ 每日备份定时
对应原型 US-12 一键启动；五阶段（技术标→商务标→合标→盖章→上传）为项目台账流程字段，不驱动系统行为
关键实现映射（原型机制 → 实现机制）：拆解模拟 1.6s → 真实解析管线（OCR 分流+结构化）；文内搜索 → DOM TreeWalker（预览模式保留）+ 后端 FTS5（跨文档）；风险指数 → 按未处理致命×6+风险×3 递减；缺件保护 → canDetect 校验；导出拦截 → pendingFatal 前置确认。

③数据架构图

十张核心表 + 两组状态机。字段与原型演示数据结构一一对应；pk=主键，fk=外键。

projects 项目
  • id (uuid)
  • code UNIQUE
  • name / role(主标|陪标) / industry
  • open(开标时间) / platform
  • cust / contact / sales
  • stage 0-4 五阶段
  • is_archived / result / note / amount
  • detected_at 最近检测
documents 文档
  • id
  • origin_path UNIQUE / stored_name
  • kind(tender|bid) / file_type
  • size / mtime 去重键
  • project_id fk→projects 可空=未绑定
  • status 0未拆解/1拆解中/2已拆解
  • content_text / doc_date
extract_items 拆解结构项
  • id
  • doc_id fk / group(招标4组|投标7项)
  • name / sum / seq
  • 表：字段值行（结构化）
materials 素材
  • id
  • type(表格|文本|图片|附件)
  • cat 七类 / tags[]
  • title / rows|text|file
  • src(文档库拆解|手动上传)
  • used 引用计数 / updated
material_refs 引用
  • material_id fk / project_id fk
  • 素材↔项目 多对多
risks 废标风险项
  • id / project_id fk
  • sev(致命|风险|提示) / type(四型)
  • title / req / quote / advice / fix
  • page_no / done / done_at
score_rows 评分对照
  • id / project_id fk
  • item / req / response
  • status(达标|缺口)
persons 人员
  • id / name UNIQUE
  • title / certs / industries
  • 档案卡 + 材料齐缺状态
watch_paths / customers
  • watch_paths: path UNIQUE / enabled / last_scan
  • customers: name / history[]（合作次数与结果）
audit_log 审计
  • ts / action / pipeline(local|glm)
  • doc_id / detail
  • 涉密红线证据链
projects 1—N documents（一个项目多份招标/投标/资料文件）
documents 1—N extract_items（拆解产出结构项）
extract_items → materials（拆解完成自动聚合入库，doc+title 去重）
materials N—N projects（经 material_refs 引用，引用计数 used）
projects 1—N risks / score_rows（检测产出，已处理闭环）
customers 1—N projects（客户合作历史聚合为徽章）

两组状态机

未拆解 0开始拆解抽取1.6s 模拟→真实解析管线拆解中 1结构项落库已拆解 2
技术标制作 0→商务标制作 1→合标 2→打印盖章 3→上传 4← 回退日程落后自动提示（isBehind）

④按推荐默认执行的决策（可推翻）

  • 成员与账号：原型有「邀请成员」弹窗与负责销售字段。按需求文档 v2.2 单机自用定位，一期按单机单用户实现——销售/角色仅作数据字段记录，邀请成员与账号体系二期（技术架构已预留）。
  • 系统设置：原型为空壳，按六组实现——通用 / AI 服务（接 GLM Key 弹窗）/ 自动归档 / 备份还原 / 规则设置 / 关于。
  • 抽取字段规则编辑器（四种抽取方式弹窗）：一期固定拆解结构先行，该编辑器二期开放（架构已预留 extract_rules 扩展位）。
  • 导出：一期做 Word（编辑区文档）+ 检测报告 Excel + 打印 PDF 三种；导出前致命项拦截确认生效。
  • 系统设置页的「原型说明」按钮属操作指导类（你定的 UI 规则），实现版移除。
